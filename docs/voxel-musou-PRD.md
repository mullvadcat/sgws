# Voxel Musou — 赵云：产品需求文档（逆向整理）

> 版本：0.1 ｜整理日期：2026-09-25 ｜依据：仓库 `main` 提交 `5702d9078d664974527ae3defe5aef49a5c4ed46`。<br>
> 文档性质：描述该提交对应的**现有可运行体验**，并标出要扩展为正式游戏时仍待决策的事项。文中“应”用于定义现状的验收口径；“建议”不代表仓库已实现。

## 1. 产品概述

Voxel Musou 是一款可在桌面浏览器中直接游玩的第三人称体素风群战动作演示。玩家操控赵云，以长枪普通连招、蓄力技、空中攻击、闪避和无双技对抗大批魏军。核心体验是在人群包围和持续增援中打出流畅连击、大范围击飞与高击破数，并通过镜头、音效、特效和书法式 HUD 获得强烈的打击反馈。

当前版本采用单战场、单角色、持续战斗模式。代码没有关卡通关、失败结算、角色成长或存档流程；主角生命值最低为 1，敌方增援可在可用槽位内持续出现。这些是当前演示的边界，不能把“击破 300 人”理解为通关目标。

### 1.1 目标用户与使用场景

| 用户 | 核心诉求 | 场景 |
| --- | --- | --- |
| 动作游戏爱好者 | 快速体验大规模割草、连招与无双演出 | 桌面浏览器打开即玩 |
| 体素/WebGL 作品体验者 | 观看密集人群、体素碎块与画面后处理 | 试玩或分享演示链接 |
| 开发者/创作者 | 研究无需构建的 Three.js 动作游戏实现 | 静态服务器运行源码 |

### 1.2 产品目标

1. 玩家无需安装或构建，打开页面并理解基本操作后即可进入战场。
2. 普通攻击、蓄力分支、移动与闪避之间形成可学习且响应明确的战斗循环。
3. 约 300 名敌兵的默认场景能够持续向玩家施压，并让击飞、击破和无双产生清晰可见的反馈。
4. HUD 始终让玩家辨认生命值、无双资源、连击数、击破数、敌将与周边敌人。

目前仓库未提供用户研究或运营数据。若要将以上目标转成商业化 KPI，需先确定发行目标、目标设备及测量方案。

## 2. 范围与体验流程

### 2.1 当前版本范围

- 平台：支持 WebGL2 的桌面浏览器；推荐桌面 GPU。键盘鼠标为主要输入，标准映射手柄可选。
- 内容：赵云一名可玩角色、黄昏城池战场、魏军兵群与 4 名具名敌将。
- 模式：单人、单场景、无明确终点的持续战斗演示。
- 运行：静态文件 + 原生 ES Modules；Three.js r186 随仓库提供，无构建步骤。

### 2.2 玩家流程

1. 打开页面，看到标题、操作说明和“出陣”按钮。
2. 点击“出陣”或按 Enter，进入战场；首次用户按键或点击后启用音效。
3. 移动、调整镜头，使用普通攻击连招；在连招节点输入蓄力攻击，或使用跳跃、空中攻击与闪避。
4. 击中或击破敌人积累无双槽；任一完整分段就绪后按 I 发动无双。
5. 通过生命值、无双槽、连击、击破、敌将血条、小地图和增援提示判断战况。
6. 按 Esc 暂停并查看操作；再次按 Esc、Enter 或点击按钮继续。窗口失焦时自动暂停。

### 2.3 操作映射

| 动作 | 键盘/鼠标 | 手柄（标准映射） |
| --- | --- | --- |
| 移动 | WASD / 方向键 | 左摇杆 |
| 普通攻击 | J / 鼠标左键 | X / □ |
| 蓄力攻击 | K / 鼠标右键 | Y / △ |
| 跳跃 | Space | A / × |
| 闪避 | L / Shift | R1；代码也接受索引 7 的按钮 |
| 无双 | I | B / ○ |
| 镜头旋转 | 鼠标拖动 / Q、E | 右摇杆横向 |
| 暂停、继续 | Esc；菜单中 Enter 可继续 | 未见手柄暂停映射 |

## 3. 功能需求与验收口径

| 编号 | 优先级 | 当前需求 | 可观察的验收口径 |
| --- | --- | --- | --- |
| FR-01 | P0 | 进入与暂停 | 首屏显示标题、操作表和开始按钮；开始后 HUD 可见；Esc 可切换暂停；失焦自动暂停；暂停时模拟不推进。 |
| FR-02 | P0 | 移动与镜头 | 玩家按镜头相对方向移动；鼠标拖动或 Q/E 可旋转镜头；角色受战场边界限制。 |
| FR-03 | P0 | 普通连招 | 连续普通攻击可依次触发 N1–N6；招式有独立的攻击判定、位移与取消窗口；按键缓冲容纳提前输入。 |
| FR-04 | P0 | 蓄力分支 | 空闲时蓄力触发 C1；在 N1–N5 的分支窗口输入蓄力分别触发 C2–C6；招式表现与攻击范围应有区分。 |
| FR-05 | P0 | 机动与空中攻击 | 支持跳跃、空中普通攻击、空中蓄力攻击、奔跑中攻击和闪避；闪避与部分攻击窗口能打断当前动作。 |
| FR-06 | P0 | 命中与受击反馈 | 命中产生打击停顿、受击动作、击退/浮空/倒地、命中特效与音效；敌人击破后有体素碎裂表现。 |
| FR-07 | P0 | 敌军群战 | 默认生成约 300 名普通兵和 4 名敌将；士兵以小队接近并形成包围圈，空位由后排补位；战场人群不足时可出现援军。 |
| FR-08 | P0 | 敌人攻击 | 敌兵攻击有前摇；同时发起攻击的人数受限制；普通兵与敌将伤害、警戒距离和生命值不同。 |
| FR-09 | P0 | 无双技 | 资源满至少一段、角色落地且未受击时可以发动；发动后有特写、冲锋、龙影、范围伤害和终结演出；一次消耗三段槽中的一段，结束后恢复控制。 |
| FR-10 | P0 | 战况 HUD | 显示主角生命值、三段无双槽、连击数、击破数、敌将姓名/血条、小地图、士气条、战场/增援提示；提示不得长期遮挡战斗主体。 |
| FR-11 | P1 | 音画表现 | 战场呈黄昏城池、旌旗、火光；支持程序化音效及景深、泛光、雾霭、复古像素化等后处理。 |
| FR-12 | P1 | 敌人数配置 | `?enemies=N` 可把普通兵槽位容量设置为 0–2000，默认值 300；容量变化不应改变输入或核心战斗规则。该参数不保证 `spawnArmy()` 一次填满全部普通兵槽位。 |

### 3.1 已确认的关键规则

- 主角初始生命值为 400；普通兵攻击伤害为 10，敌将攻击伤害为 22。当前主角生命值最低为 1，不触发死亡。
- 普通兵初始生命值为 30，队长为 80，敌将为 520。敌将当前有 4 个槽位，并可随增援再次出现。
- 无双资源上限在逻辑中记为 100，HUD 显示为三段；达到约三分之一即可发动一次无双。
- 击中敌人会增加连击；仅在非无双状态下，命中会增加无双资源，首次击破额外增加资源。无双期间造成命中或击破均不得增加无双资源。主角在可受伤状态下被击中也会少量获得无双资源。
- 敌军总容量是配置的普通兵数量加 4 个敌将槽位；“约 300 人”指默认普通兵配置，不是同时保证可见或永久累计击破上限。
- 士气条由击破数和当前存活敌人数计算，用于战况表现；当前未发现士气改变敌人能力或触发胜利的规则。

## 4. 界面与反馈需求

| 区域/时机 | 信息与行为 |
| --- | --- |
| 首屏/暂停菜单 | 项目名称、基本操作、出阵/继续入口；暂停后隐藏战斗 HUD。 |
| 底部主角区域 | 人物标识、生命值与三段无双槽；资源达到一段时应有就绪反馈。 |
| 战斗中 | 连击数、累计击破数；达到击破里程碑时突出显示。 |
| 敌将交战 | 目标敌将血条、场上敌将头顶姓名与血条；击破时显示横幅。 |
| 战场态势 | 小地图显示周边单位、敌将和援军提示；士气条呈现蜀魏对比。 |
| 无双演出 | 镜头切换、龙影、色调变化、范围击飞和结束台词共同表达技能阶段。 |

界面用繁体中文为主，并包含英语辅助文字。仓库提供简体中文、英语和日语 README，但游戏内未发现语言切换设置。

## 5. 非功能需求与运行约束

| 编号 | 要求/现状 | 验收方式 |
| --- | --- | --- |
| NFR-01 | 需 WebGL2 浏览器；应由静态服务器提供，`file://` 方式不适用。 | 在支持 WebGL2 的桌面浏览器中以静态服务启动并进入战斗。 |
| NFR-02 | 游戏逻辑以固定 60 Hz 步进；渲染帧率是设备与负载结果，仓库未承诺最低 FPS。 | 用稳定与不规则两种渲染调度推进同一逐模拟步输入脚本和相同模拟步数，规则快照一致；另验收单帧补步上限、积压丢弃及暂停恢复时输入边沿不重复消费。 |
| NFR-03 | 默认普通兵槽位容量为 300；可通过 URL 参数测试 0–2000 的容量边界。`?enemies=2000` 是 2000 槽位容量档，不等同于 2000 名普通兵同时生成或参战。 | 在 0、300、2000 三档核对加载、生成与可操作性；记录配置容量、初始实际生成数、采样期间存活数、渲染实例数、所用设备和实测帧率，不得仅以数组容量判定 2000 档通过。 |
| NFR-04 | 无构建步骤；第三方 Three.js 文件内置。 | 用静态服务器托管仓库根目录即可运行，不依赖包安装。 |
| NFR-05 | 音频受浏览器交互策略约束，首次按键或点击后开始。 | 首次交互后可听到音效；未交互时不将静音误报为故障。 |

当前未提供正式性能基线、浏览器兼容矩阵或自动化验收数据，不能从固定 60 Hz 逻辑推断“稳定 60 FPS”。

## 6. 范围外与待决策事项

以下事项未在当前提交中形成完整产品机制。如计划做正式发行版，建议按顺序决策：

1. **关卡目标与结算**：采用限时击破、护送、击败指定敌将还是其他目标；胜负条件、重试入口和成绩页如何定义。
2. **生存与难度**：是否允许主角死亡；敌将刷新频率、伤害与资源增长如何与目标时长平衡。
3. **性能与平台**：目标桌面设备、浏览器、分辨率和帧率门槛；是否增加画质档位或移动端触控。
4. **内容扩展**：是否增加角色、武器、关卡、剧情、成长、存档、排行榜或多人模式。
5. **本地化与可访问性**：游戏内语言切换、按键重映射、字幕、特效强度和色彩辨识选项。
6. **发行与权利**：项目声明其为与 KOEI TECMO 无关的同人作品，代码为 MIT；正式商业发布前需要独立确认角色、名称、商标和内容的使用范围。

这些条目是产品化议题，不纳入本文件对当前演示的验收。

## 7. 当前版本验收场景

1. **开局**：静态服务器启动页面；首屏展示控制说明；点击“出陣”后出现主角、敌军和 HUD。
2. **连招分支**：连续按 J 打出 N1–N6；在 N1 后按 K 进入 C2；空闲按 K 进入 C1。
3. **移动战斗**：落地连续奔跑达到 `runT >= 14` 后按 J 触发突进动作；奔跑未满14帧时按 J 仍从 N1 开始；奔跑跳跃落地且仍保持方向输入时，保留的 `runT` 达到阈值也可触发突进。跳跃中按 J 或 K 出现对应空中攻击；Shift/L 触发闪避。
4. **大规模战斗**：默认配置下敌军会聚拢、补位并在减员后出现援军；命中、击破、连击和敌将提示同步更新。
5. **无双**：累积至少一段无双槽后按 I，完整播放演出与范围攻击；无双命中或击破不产生无双资源，结束后槽位准确减少一段并恢复操作。
6. **暂停与边界**：Esc 与失焦会暂停；恢复后不因按住菜单按键而误触发战斗动作；`?enemies=0` 与 `?enemies=2000` 均可加载。
7. **当前无终局**：主角受到足量伤害后 HP 停在 1；持续击破敌军不会出现胜利或失败结算画面。
